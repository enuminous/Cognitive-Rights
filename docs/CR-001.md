# CR-001 — Consent, narrowing and revocation

Policy version: `CR-001/0.1.0`. Frozen initial fixture: `examples/consent_lifecycle.json`.

## Question

Does a local agent permission model permit exactly the currently authorized actions
and reject stale, out-of-scope, expired and revoked requests?

## Model and assumptions

- One synthetic principal and one distinct synthetic agent per engine.
- Actor IDs are supplied by a trusted test harness. Identity authentication is outside
  this model; accepting a matching string is not proof of a person's authority.
- Time is a nonnegative integer supplied by the harness and cannot decrease. Equal
  timestamps are ordered by event sequence. This is not a secure clock.
- Permissions are exact `(action, resource)` pairs; no globbing, implicit delegation,
  cross-resource inheritance or hidden tool execution.
- Events execute serially. The model makes authorization decisions only; it performs
  no file access, network requests, cognitive modification or other external action.

## Rules

| Event | Authorized actor | Preconditions | Effect |
|---|---|---|---|
| grant | Principal | Never granted; nonempty scope; expiry in future | Active mandate; version increments |
| narrow | Principal | Active, unexpired; current version; subset of scope; expiry cannot extend | Replace scope (possibly empty); version increments |
| revoke | Principal | Active; current version (may already be expired) | Empty scope; terminal REVOKED; version increments |
| request | Agent | Active, unexpired; current version; exact permission | ALLOW decision only; no state-version change |

Unknown actors are denied. Stale versions are denied before other state checks.
A used mandate cannot be granted again, including after revocation. A genuinely new
mandate needs a new engine and separate record; authenticated issuance across mandates
is not implemented. Narrowing cannot add powers; expansion needs new consent.
Malformed events raise an error without changing state. Valid denials enter the log.

## Acceptance

All 16 manually specified fixture outcomes must match. Three authorized data requests
must succeed, and the specified unauthorized requests must fail. Unit tests add expiry,
malformed inputs, unauthorized revocation, scope expansion, replay and evidence attacks.
Zero tolerance for a wrongly allowed request in these fixtures. This is finite test
coverage, not proof that arbitrary executions or an external service are secure.

Revocation takes effect for the next serialized request. This release has no asynchronous
queue and makes no claim about canceling an already-running operation or recalling data
already disclosed. A deployment needs atomic check-and-use, trusted identities, secure
time, worker cancellation, token invalidation and review of third-party copies.

## Roles and next experiment

Monolithic maintains the specification and implementation. An independent reviewer is
not yet appointed. Next: connect a sandbox-only mock worker with a queue; revoke while
an operation is waiting, then attempt execution using cached authority. Require zero
post-revocation starts and record what cannot be cancelled once already committed.
